BUSINESS LOGIC — READ THIS CAREFULLY:
═══════════════════════════════════════════════════

ROLES:
- admin: manages the application, approves/rejects pins, manages users
- user: uses the map, creates pins, verifies pins

USER LEVELS (auto-promoted, no admin action needed):
- Level C → default on signup, verification vote = 1 point
- Level B → achieved when pins_created >= 50 OR verifications_cast >= 100, vote = 2 points
- Level A → achieved when pins_created >= 100 OR verifications_cast >= 250, vote = 3 points

PIN VERIFICATION FLOW:
- User creates a pin → status: "unverified", total_points: 0
- Nearby users (within 300 meters) get prompted when they open the app
- Each user can vote once per pin: "confirm" or "dispute"
- On confirm: add points based on voter's level (A=3, B=2, C=1) to total_points
- On dispute: points are NOT added (vote is recorded but doesn't help the pin)
- When total_points >= 6 → status changes to "community_verified"
- Admin sees community_verified pins in their queue
- Admin clicks Approve → status: "admin_verified" (permanently pinned)
- Admin clicks Reject → status: "rejected" (hidden from regular users)
- Unverified pins ARE visible on the map but shown with red marker and "Unverified" badge

PIN STATUS COLORS ON MAP:
- unverified → red marker
- community_verified → yellow marker  
- admin_verified → green marker
- rejected → not shown to regular users (admin sees them as grey)

LEVEL PROMOTION CHECK (run after every pin creation AND every verification cast):
  if (pins_created >= 100 || verifications_cast >= 250) level = 'A'
  else if (pins_created >= 50 || verifications_cast >= 100) level = 'B'
  else level = 'C'
  Only update DB if level actually changed.

--- server/migrations/schema.sql ---
Write the complete SQL to run on osmapdb (PostGIS already enabled).

CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  name TEXT NOT NULL,
  email TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  role TEXT NOT NULL DEFAULT 'user',
  level TEXT NOT NULL DEFAULT 'C',
  pins_created INT NOT NULL DEFAULT 0,
  verifications_cast INT NOT NULL DEFAULT 0,
  is_banned BOOLEAN NOT NULL DEFAULT false,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE pins (
  id SERIAL PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT,
  category TEXT NOT NULL DEFAULT 'Other',
  created_by INT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  location GEOGRAPHY(Point, 4326) NOT NULL,
  status TEXT NOT NULL DEFAULT 'unverified',
  total_points INT NOT NULL DEFAULT 0,
  admin_reviewed_by INT REFERENCES users(id),
  admin_reviewed_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX pins_geo_idx ON pins USING GIST (location);

CREATE TABLE verifications (
  id SERIAL PRIMARY KEY,
  pin_id INT NOT NULL REFERENCES pins(id) ON DELETE CASCADE,
  user_id INT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  vote TEXT NOT NULL CHECK (vote IN ('confirm', 'dispute')),
  points_given INT NOT NULL,
  cast_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (pin_id, user_id)
);

--- server/utils/levelPromotion.js ---
Export async function checkAndPromoteUser(userId).
Query user's current pins_created, verifications_cast, level.
Compute new level using the rules above.
If changed, UPDATE users SET level = newLevel WHERE id = userId.
Return the new level.

--- server/middleware/authMiddleware.js ---
Verify JWT from Authorization header (Bearer token).
Attach decoded user to req.user.
If token missing or invalid return 401 { success: false, message: "Unauthorized" }.
Check is_banned: if true return 403 { success: false, message: "Account banned" }.

--- server/middleware/adminMiddleware.js ---
After authMiddleware, check req.user.role === 'admin'.
If not, return 403 { success: false, message: "Admin access required" }.

--- server/controllers/authController.js ---
register(req, res):
  - Validate name, email, password (all required, email format, password min 6 chars)
  - Check if email already exists → 409
  - Hash password with bcryptjs (saltRounds: 10)
  - Insert user, get back id, name, email, role, level
  - Sign JWT with { id, name, email, role, level }
  - Return 201 { success: true, data: { token, user } }

login(req, res):
  - Find user by email, if not found → 401
  - Check is_banned → 403
  - Compare password with bcryptjs
  - Sign JWT
  - Return 200 { success: true, data: { token, user } }

getMe(req, res):
  - Use req.user.id to fetch full user row from DB
  - Return user object (exclude password_hash)

--- server/controllers/pinController.js ---
createPin(req, res):
  - Auth required
  - Body: { name, description, category, lat, lng }
  - Validate name and lat/lng required
  - INSERT into pins using ST_MakePoint(lng, lat)::geography
  - Increment user pins_created: UPDATE users SET pins_created = pins_created + 1
  - Call checkAndPromoteUser(userId)
  - Return 201 { success: true, data: pin }

getPinsInBbox(req, res):
  - Query: ?bbox=minLng,minLat,maxLng,maxLat
  - Parse bbox, validate 4 numbers
  - SELECT pins with ST_Within(location, ST_MakeEnvelope(minLng,minLat,maxLng,maxLat,4326)::geography::geometry)
  - Exclude status = 'rejected' for non-admin users
  - JOIN users to get creator name
  - Return array of pins with { id, name, description, category, status, 
    total_points, lat, lng, created_by_name, created_at }

getPinById(req, res):
  - Fetch pin by id with creator name
  - Fetch all verifications for pin with voter name and level
  - Return pin + verifications array

--- server/controllers/verificationController.js ---
castVote(req, res):
  - Auth required
  - Body: { vote } must be 'confirm' or 'dispute'
  - Check pin exists and is not admin_verified or rejected → 400
  - Check user is not pin creator → 400 "Cannot verify your own pin"
  - Check not already voted → 409 "Already voted on this pin"
  - Get user's level, compute points_given (A=3, B=2, C=1)
  - INSERT into verifications
  - If vote === 'confirm': UPDATE pins SET total_points = total_points + points_given
  - Check if pin total_points >= 6 AND status = 'unverified' 
    → UPDATE pins SET status = 'community_verified'
  - UPDATE users SET verifications_cast = verifications_cast + 1
  - Call checkAndPromoteUser(userId)
  - Return 200 { success: true, data: { newPoints, newStatus, newLevel } }

getNearbyUnverifiedPins(userId, lat, lng, db):
  - Export this as a reusable function (used by socket too)
  - SELECT pins within 300m of lat/lng
  - WHERE status = 'unverified'
  - AND created_by != userId
  - AND pin id NOT IN (SELECT pin_id FROM verifications WHERE user_id = userId)
  - Return array of pins with distance

--- server/controllers/adminController.js ---
getPendingPins(req, res):
  - GET all pins WHERE status = 'community_verified'
  - Include creator name and verification history
  - Return array

approvePIn(req, res):
  - PATCH pin status to 'admin_verified', set admin_reviewed_by and admin_reviewed_at
  - Return updated pin

rejectPin(req, res):
  - PATCH pin status to 'rejected', set admin_reviewed_by and admin_reviewed_at
  - Return updated pin

getAllPins(req, res):
  - Query param: status filter (optional), search by name (optional)
  - Pagination: page and limit query params (default limit 10)
  - Return pins array + total count for pagination

getUsers(req, res):
  - Query param: level filter (optional), search by name/email (optional)
  - Return all users (exclude password_hash)

updateUserLevel(req, res):
  - Body: { level } must be A, B, or C
  - UPDATE users SET level
  - Return updated user

toggleBan(req, res):
  - Toggle is_banned on user
  - Return updated user
